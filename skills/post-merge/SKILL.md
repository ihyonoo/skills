---

## 1. 머지를 확인한다

정리 전에 실제로 머지됐는지 확인한다. `gh pr view <번호>`의 상태 또는 원격 기본 브랜치의 로그로 본다.

머지가 확인되지 않으면 **정리하지 않는다.** 확인되지 않았다는 사실을 보고한다.

## 2. 알리고 확인받는다

무엇을 할 것인지 한 줄로 말하고 승인을 받는다. 브랜치 삭제는 되돌리기 번거로운 작업이다.

## 3. 정리한다

```
git checkout <기본 브랜치>
git pull origin <기본 브랜치>
git branch -d <머지된 브랜치>
```

`-d`가 거부하면 **그 브랜치는 머지되지 않았다.** `-D`로 강제하지 않는다. 거부됐다는 사실과 남아 있는 커밋을 보고하고 판단을 넘긴다.

## 4. 남은 것을 확인한다

- 원격에 삭제 안 된 브랜치가 있으면 알린다(삭제는 확인받고)
- 스태시나 커밋 안 된 변경이 남아 있으면 알린다
- 다른 머지된 브랜치가 더 있으면 함께 정리할지 묻는다

## 하지 않는 것

- 확인 없이 브랜치 삭제
- `git branch -D`로 강제 삭제
- `git reset --hard`, `git clean` 같은 파괴적 명령으로 "정리"하기
